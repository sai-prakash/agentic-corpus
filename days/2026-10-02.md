Turbo Harness (2609.40330, Zhang / Wang / Xu / Metaxas, submitted 30 Sep, announced 1 Oct): a global harness is not an instance harness. Existing optimizers emit one cage and apply it uniformly. Turbo recycles artifacts from a finished global run into a structured playbook, then trains an editor that patches that cage per instance at inference. Seven benchmarks spanning interactive agents, software engineering, and long-horizon terminal tasks; the abstract says it beats existing harness-optimization baselines and does not report per-bench deltas. No public method repo. Heat 4 under harness-evolution / agent-harness. Pair with MOSIB: branch routing picks a complementary head; Turbo rewrites the head for the instance. Do not treat "consistently outperforms" as a measured lift.

Mid-Harness (2609.39982, Kang / Hachiuma / Zhang / Radhakrishnan / Fu / Jiang / Liu / Hosseini-Asl / Dong / Wang / Lee, submitted 30 Sep + byungkwanlee.github.io/MidHarness-page/): sampling actions is not a stronger harness. Generator and harness stay fixed; candidate actions are sampled and verified before one is forwarded. On TerminalBench-Lite, a GPT-5.6 Sol verifier raises Pass@1 from 50.00% (base agent) to 68.03% with 8 sampled actions. With a TMAX-9B generator, more samples do little under weak verification; a capable verifier can use the alternatives. Distilling the stronger verifier into TMAX-9B lifts Pass@1 without changing the action generator. Combining action and trajectory scaling beats generating more trajectories alone on estimated token cost. Heat 4 under agent-harness / evals-gates. Pair with Turbo: one edits the cage, the other gates the act.

ScholarEvolve (2609.40169, Yang / Lai / Wang / Harari / Gabrilovich / Chang, submitted 30 Sep): failure-only evolution is not literature-guided evolution. A meta coding agent that only patches from its own knowledge and observed failures stays reactive. ScholarEvolve splits the harness into functional modules, uses topic modeling to name distinct improvement strategies per module, implements combinations, and can ingest new papers over time. Qwen3.5-27B AppWorld Challenge goal completion 49.6% → 63.6%; GPT-5.4-mini Tau2-Bench Telecom pass@1 72.7% → 81.9%. No public repo in the abstract. Heat 4 under harness-evolution. Pair with Growing Harness and MOSIB: localize a failure, route a branch, or import a paper — three outer loops, not one.

Thin MLE harness (2609.40303, Brilliantov / Hernández-Cano / Abbé, submitted 30 Sep): an elaborate MLE harness is not a stronger coding agent. Under an equal time budget and the same frontier LLM, open-source state-of-the-art MLE harnesses (orchestrators, retrieval subagents) showed no advantage over a single session of a minimal coding agent with read / write / bash. Ablations argue the machinery is redundant on current MLE benches; the backbone is the driver. No per-system deltas in the abstract. Heat 4 contrast under agent-harness. This is a domain bound, not a license to delete gates on long-horizon coding. Pair with MOSIB / Growing Harness: those lifts were measured where the cage still moved the score.

MILO (2609.38349, Jana / Goswami / Liu / Li / Huang / Huang / Huang / Blöbaum / Deoras / Jain / Kanakaris / Genc, submitted 29 Sep, missed yesterday): a fixed search policy is not a co-evolved search. Island lineage memory treats rejected mutations as negative evidence; per-island mutators rewrite whole harnesses; an orchestrator grafts lineages, reassigns mutators, and revises the curriculum. Opus 4.8 resolution over the initial harness: Terminal-Bench 2.1 +12.0%, PaperBench +28.3%, DeepSWE +10.3%, against best prior-search gains of +4.5%, +18.3%, and 0%. Terminal-Bench 2.1 86.1 ± 2.0% vs the official leaderboard top 83.8 ± 2.3%, with 26% fewer tokens than its initial harness. EinsteinArena: Erdős minimum-overlap upper bound 0.3808586 → 0.3808568; autocorrelation inequalities 1.50274365 → 1.50274360 and 1.45081 → 1.44889. No method repo in the abstract. Heat 5 under harness-evolution. Pair with MOSIB: one co-evolves the search, the other co-evolves branch objectives.

Context Language Models (2609.37725, Shao / Shen / Yin / Li / Wang / Ivison / Poovendran / Lambert / Xiao / Lewis / Yih / Zettlemoyer / Koh; UW, Meta Superintelligence Labs, MIT, Trillium Labs; submitted 29 Sep + github.com/facebookresearch/context-language-models; recirculated 1 Oct by Prasenjit Sarkar, @stretchcloud): a hand-coded compaction rule is not a context file the model edits. The context is a file; the model may append tokens or Bash-edit it, and the edit syncs into the live context. Multiple agent contexts coexist as files. Zero-shot CLMs vs SOTA context management: BrowseComp-Plus +11.4% accuracy and 21.5% fewer FLOPs; 12-hour EdgeBench +5% scores and 59% fewer FLOPs; 24-hour multi-repo agent swarm +65% improvement at the same compute. A skill-optimization loop on natural-language context instructions: up to +35.9 held-out points on a context-management task while reducing compute. Online RL: Qwen3.5-9B BrowseComp-Plus +47.6% accuracy and 12% fewer FLOPs. Suffix Cache Reuse cuts server-side compute 35% vs standard SGLang at matched performance — the tax is broken prefix caching. Heat 5 under memory-lifecycle. Pair with Traverse: Seal is an agent-invoked summarize-reset-continue tool; CLM is unrestricted file edit. Do not read the 65% swarm line as a model result.

MAS mechanism diagnosis (2609.38761, Zhengye Han, submitted 30 Sep): a correct answer is not a clean collective mechanism. A diagnostic contract separates what counts as a violation (route, admit, store, act on shared information) from which records can establish one, and returns supported / ruled out / unknown. Removing records can make a conclusion unknown; it cannot reverse one. Replay from the step a mechanism acts: unchanged, broken, restored. Broken mechanisms often left the answer correct. An LLM diagnoser saw many more violations in internal records than in public outputs; a generic prompt claimed certainty the same records did not support, and contract prompts largely avoided that. A near-perfect diagnostic behavior on their bench degraded on an independently developed workflow. Heat 4 under evals-gates. Pair with MAADBench: a room pass is not a step-clean trace, and a right answer is not an intact collective mechanism.

Arm A: one searched global harness, applied to every instance. Arm B: a playbook of rejected and accepted edits from Arm A's search; an editor may patch only the missed instances.

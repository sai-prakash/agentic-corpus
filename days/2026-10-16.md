Harvey context graphs (X post by @nikogrupen, 15 Oct, high engagement ~200 likes / 300 bookmarks): agent first builds a per-matter graph of entities and relationships (parties, dates, draft vs executed, version links) from client documents, then solves LAB tasks. With graph vs raw files: up to +30% rubric pass rate, up to ~50% lower task cost. One firm-knowledge example: raw-files agent selected wrong precedent (0%); graph agent found the right matter and executed agreements immediately (75%). Product evidence that a task-specific context graph improves online agent quality and efficiency. Single post + internal experiments; not yet a paper. Heat 4. Contrast: not a static knowledge graph or flat memory; a runtime slice the agent assembles then discards.

STRATA (arXiv:2610.19386, Zhu et al., submitted 14 Oct): three-layer self-maintaining experience graph (atomic skills/snippets, workflows, meta-frameworks) with typed edges and five maintenance mechanisms (multi-dim similarity, typed reflector, community detection, pressure GC with articulation-point protection, contrast edges). Best average on AppWorld/WebArena/ALFWorld/ScienceWorld, lowest latency/fewest steps among memory methods, 44% fewer injected lines; contrast edges lift ScienceWorld 78.7→96.7 by blocking negative transfer. Still single paper, no shipping repo. Signal, heat 3.

EGCForest (arXiv:2610.19836, Cui et al., submitted 14 Oct): multi-view hierarchical memory for enterprise group chats. Immutable log into Channel/Actor/Artifact forests + Placement Map and sparse bridges. Up to +20.85 accuracy over MemOS on enterprise-chat benchmarks. Single paper; signal, heat 3.

Coding agent harness design (arXiv:2609.20804, Fan et al., submitted 17 Sep; discussed on X 15 Oct by @MikeTamir and others): 176 settings across planning, action space, and context management on SWE-Bench Verified + Terminal-Bench. Key: context management value rises as window tightens (mostly by preventing overflow); rule-based elision before LLM summarization is strongest efficiency; planning helps weaker models as accuracy scaffold, stronger as cost saver; predefined tools help bash-weak models, bash-only is cheaper for capable ones. Older paper, but active discourse. Heat 3 on the discussion.

DKGI (arXiv:2610.18616 + github.com/leopoldwhite/DKGI) remains the strongest recent shipping harness example: agents write/revise Python over node+edge files, co-evolving tools with use, ≥6.7 Hit@1 over baselines. Already in graph.

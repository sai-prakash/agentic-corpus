Harness-of-Harness (2609.01481, Yan / Su / Zhang et al., 1 Sep; repo Flesymeb/HarnessOfHarness, project page live 2 Sep): the object that evolves is not the coding agent. HoH sits on existing harnesses (Codex+GPT-5.5, OpenCode+DeepSeek-V4-Pro, Pi+MiniMax-M3) and runs iterative plan–code–test loops. Planner writes a prioritized development document and does not touch the artifact. Implementation-time tests stay inside the loop; independent evaluation scores the iteration. Deliverables, role-specific tools, and skills are exposed progressively. Reuse is preferred to recreation. Project history is versioned. Average relative gain 52.25% after three iterations, max 82.86%, across GameCraft-Bench, FrontierSWE, and ProgramBench. Multi-day run: 70+ iterations produced a playable first-person shooter. Contrast with EvoUndo and Warp: HoH separates the tests the agent writes from the gate that accepts the iteration. A score the implementer invented is not the score.

HarnessEvolve (2609.00829, Jiang / Chu / Tian et al., 1 Sep): self-evolution fails three ways — terminal success/fail cannot assign credit; the agent memorizes the batch; unguarded edits forget earlier competence. The fix is to split roles. Execution, evaluation, optimization, and gating are separate modules. Failed runs are aligned against reference trajectories produced when the ground-truth answer is given; clustered diffs become the error signal. Two gates: quality (leakage score ≤ 0.8, in-context examples ≤ 5) and performance (current-batch accuracy must not fall, recent-batch degradation ≤ 0.025), with a held-out snapshot pick at epoch end. CloudCoreNetwork-QA, Qwen: 43.4% base → 86.9% HarnessEvolve vs 65.3% GEPA. SpreadsheetBench: 44.3% → 76.4%. No public repo yet. Pair with Warp's human merge and EvoUndo's recoverability: a harness diff that raises this batch is not admissible until it does not drop the last batches and can be rolled back to a stored snapshot.

Selective Forgetting (2608.28978, Rusu / Khanzadeh / Alalfi, 29 Aug; code skhanzad/Selective-Amnesia; Elvis 2 Sep): the graph-memory assumption is measured and loses. Conversational turns extracted into typed nodes and attributed edges, answers from a two-hop subgraph, candidate-generation budget fixed at five retrieval roots. LongMemEval token F1 0.417 graph vs 0.468 flat vector; paired bootstrap over 500 questions Δ = −0.050 (95% CI −0.085 to −0.016). The damage is concentrated on questions that need a specific prior assistant turn: judged correctness 0.911 → 0.607. Splitting a turn into entities discards the surface form those questions depend on. Forgetting is the cheap win. One prune of a 27,021-node graph on recency, access frequency, degree centrality, and age removes 9.8% of nodes and 9.5% of stored bytes; token F1 unchanged (+0.001). This is the measurement under yesterday's memoryfield contrast: High Modernist extraction is not recall. Keep the page. Delete the isolated proposition.

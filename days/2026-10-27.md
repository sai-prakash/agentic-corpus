# 2026-10-27

ActionRAG (arXiv:2610.32752, Mahla & Vandrangi, submitted 23 Oct): graph memory architecture that couples cautious indexing (label reconciliation, tiered entity resolution) with query-time graph retroevaluation via receiver-normalized diffusion on a bounded local evidence graph. Dual-channel entity+triple retrieval + seed protection + hub-penalized flux materializes missed connections. On MemoryAgentBench eight deterministic columns: 55.1 avg accuracy (+5.4 over strongest retrieval baseline). Mean synthesis cost < $0.001/query; retrieval p99 components sum 440.7 ms on Apple Silicon. Contrast: initial similarity scores are not final; local path structure revises them. Heat 4. X shares circulating.

HarnessMM (arXiv:2610.32813, Jiang et al. Tsinghua/MSRA, submitted 23 Oct): improves harness token efficiency by guarded decision reuse. Executable Decision Graphs store exact actions, literal arguments, dependencies and public guards. Controller at model-tool boundary reuses resolved decisions (weights fixed); new semantics, unsupported evidence or abstention fall back to the actor. RSI refines companion configs. HumanEval/Codex: success held 90.82%, tokens/task 66.72k → 47.02k (-29.5%). DeepSeek harness: success 71.43% → 85.71%, tokens 96.28k → 11.62k (-87.9%). MBPP ablation: 26.9% lower cost than single-use graphs. Contrast: the harness does not re-reason after every tool result when the next action is already fixed. Heat 4. Multiple X posts quoting the numbers.

Knowledge fabric (Sarvam AI blog, 26 Oct): organizes enterprise data into a knowledge tree (hierarchical indexes, summaries, tables) + domain ontology (entities, properties, relations) *before* retrieval. Queries resolve to artifact identifiers that constrain vector search; disambiguation is structural. On Harvey LAB (9k files, 250 tasks, GLM 5.3): ontology+tree 84.2% rubric criteria (vs 55.1% agentic RAG), $0.28/task (vs $0.64), 0.86M tokens (vs 1.80M). Outperformed reported GPT-5.6 Sol (79.1%) and Opus 4.8 (71.7%). Contrast: organize (tree + ontology) before you retrieve; do not retrieve then organize. Heat 4.

Katelyn Lesse (@katelyn_lesse, Anthropic platform, 26 Oct, high engagement ~3k likes / 6k bookmarks): multi-agent systems at scale create new software engineering problems — infrastructure for bursty stateful agents, agent identity/authorization (especially on-behalf-of and agent-to-agent trust), security/isolation of untrusted code and content, and monitoring/kill switches that cannot be modified by the agents themselves. Signal that the orchestrator/swarm model is hitting production constraints. Heat 3 (discourse).

# 2026-11-07

MedGraph: Maintaining Patient State with Graph Memory for Long-Term Medical Dialogue (arXiv:2611.08433, Donghua Zhang et al., submitted 5 Nov 2026): LLM medical assistants that follow a patient across visits need memory that keeps clinical state correct as it changes. Five existing systems fail by retrieving outdated state, another person's facts, or omitting a safety fact the answer depends on. MedGraph extracts dated facts per session, attributes each to the person, and links medication / diagnosis / measurement into chains that preserve earlier states. Retrieval ranks patient chains as units, reads at the question time, adds original dialogue, and always includes a safety-fact profile. On MedMemoryBench, +10.5 / +10.4 points over strongest of five baselines (GPT / Qwen). Contrast: a retrieved fact that is outdated, misattributed, or missing safety is not a valid clinical state. Heat 4. Paper.

ReConMem: A Graph-Based Dual Memory System for Repository-Oriented Conversations (arXiv:2611.07759, Zhishuo Yang et al., submitted 5 Nov 2026): code assistants need joint conversational history and repository structure; general memory systems do not coordinate the two. Dual graphs: semantic (distilled natural-language memories) and structural (conversation-relevant code entities organized by repository). Cross-graph associations maintained. Recall combines NL and code-aligned retrieval (code-draft query grounding), expands over relations, compresses code by structural granularity. On LoCoEval +7.9 / +7.3 pp Pass@1 (single- / multi-hop) vs strongest baseline at comparable compression; on CodeAssistBench 27.6% Correct / 44.0% Partially Correct, beating Full History. Contrast: a general-purpose conversation memory is not aligned with the repository code entities it refers to. Heat 4. Paper.

Components of Agent Memory + Dreaming (Anthropic Engineering, Lance Martin, 6 Nov 2026; circulating on X): memory is knowledge from experience retained between sessions (not weights, not in-context, not compaction). Hierarchy: raw transcripts → notes → representations (wiki) → small injected context. Dreaming runs offline: reflects on logs, corrects mistakes (tests notes against transcripts), builds linked representations, floats salient notes to the top so the harness can pre-load them. Quantitative: wiki + search 61% vs search 53% on large internal corpus (~20k tokens saved); Harvey multi-doc merger 87% vs 73%; CL-Bench gains; smaller memory folder in Pokémon let a stronger model progress further. Contrast: writing notes during the task is not the same as offline consolidation that corrects errors and builds searchable structure. Heat 5. Shipping product + discussion.

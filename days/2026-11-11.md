# 2026-11-11

**Agency**: System Optimizations for Cost-Efficient Agent Harnesses (arXiv:2611.12122, Jongseok Park, Jiaxiang Yu et al. from UC Berkeley and others, submitted 9 Nov 2026): task accuracy depends mostly on the LLM; harness-side changes (system prompts, tools) have minimal effect on pass rate but can reduce cost up to 2.6× on the same model and task. Agency is a harness interposition platform that provides a unified abstraction between an unmodified harness (Claude Code, OpenAI Codex) and the computer, enabling portable optimizations such as tool-output compaction, context garbage collection gated by a decision-tree prediction of savings, a prebuilt SQLite index for metadata-assisted search, and a subtask stack machine. On coding and document-lookup benchmarks it achieves roughly 0.77× average cost (reductions up to 35%) while retaining 0.97× accuracy. Contrast: the harness is not the accuracy bottleneck; it is the cost bottleneck. Heat 4. Paper + detailed independent analysis on X.

**MIRIX-2.0**: Multi-Agent Memory System (arXiv:2611.12068, Wei-Chieh Huang, Weizhi Zhang, Jiayan Nan, Peng Xia, Yu Wang, submitted 9 Nov 2026): six typed memory agents keep complete records as the system of record; a provenance hypergraph indexes episodic and semantic records with n-ary frames that cite their source rows; retrieval is budgeted so the evidence examined does not grow with history. AutoDream runs offline outside the write path: it merges duplicate anchors without rewriting any record and distills task sessions into skills. Results: 91.4% on LoCoMo (leading the strongest baseline by 14.3 points), 72.6% on LongMemEval-S; highest mean success among compared memory methods on ALFWorld and WebShop; 49.2% on MetaClaw-Bench versus 44.0% for a skill library. With AutoDream disabled it is faster than HyperMem on timed benchmarks. Needs no fine-tuning; code is public. Contrast: complete, citable records plus offline distillation is not history rewriting or unbounded search. Heat 4. Paper + author posts + public repo.

**SciMARS**: Multi-Agent Recursive Self-Improvement for Closed-Loop Scientific Discovery (arXiv:2611.12552, Weimin Wu, Han Liu, submitted 9 Nov 2026): multi-agent teams for scientific discovery lose observations without shared memory and perpetuate mistakes with fixed roles, handoffs, and memory policies even when evidence is retained. SciMARS adapts roles and coordination via separate component editors guided by candidate probes; SciMARS + Memory adds an editor for how agents record, retrieve, and receive evidence, all over a shared evidence graph. On Autonomous Science Bench it resolves 12/18 GPT-6-Astra attempts (versus 8/18 for the base team) and 2/18 GLM-5.3; it also improves on ScienceAgentBench (14/38 versus 11/38) and AppWorld (11/20 versus 5/20). Official repo provides harness components. Contrast: static multi-agent procedures are not adaptive to evolving evidence. Heat 4. Paper + shipping repo.

**ToolSpace**: Scaling Tool-Centric Environment Synthesis for Long-Horizon Agents (arXiv:2611.05036, Guanting Dong et al., submitted 3 Nov 2026): existing MCP environment scaling is data-centric (synthesize a database and scenario, then derive tools and tasks), so interfaces may not match real ones and tasks rarely span environments. ToolSpace reverses the order: it mines data, state, and retry dependencies from adjacent calls in real MCP service traces and open corpora using deterministic rules (not LLM judgment), clusters the weighted tool-composition graph into environments, synthesizes databases only for state-mutating clusters, and generates tasks via state-aware random walks that must replay successfully. It produces harder Pro versions of AutomationBench and τ³-Bench on which frontier models drop by up to 38.2 points, and lifts Qwen3.6-35B-A3B from 23.0 to 41.0 average across seven long-horizon benchmarks. Contrast: environments derived from real tool compositions are not invented databases with matching tools. Heat 4. Paper + project site + recent discussion.

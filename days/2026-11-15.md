# 2026-11-15

**MULTILOOP (Evolving Multi-Agent Harnesses)**: Multi-agent harness optimization (arXiv:2611.15754, Daniela Gottesman, Gal Yona, Ori Ram, Zorik Gekhman, Jonathan Herzig, Mor Geva, Roee Aharoni, submitted 11 Nov 2026, accepted NeurIPS 2026 CL4FMAgents Workshop): single-agent harness optimization via coding agents on traces is known, but multi-agent systems require changing interactions, not just individual behavior. MULTILOOP is a simple loop where a coding agent analyzes rollouts, diagnoses failures (hallucinations, query errors, error handling, missing tools, orchestration issues), edits the harness, and re-evaluates. With 10 training samples on DeepSearchQA, the evolved multi-agent harness improves accuracy 4.6% over base and 3.2% over best single-agent. Orchestration failures persist, pointing to need for structural changes in delegation and sharing. Contrast: editing single-agent prompts/tools is not editing multi-agent interaction patterns. Heat 4. Paper + HTML/OpenReview.

**Logfire harness tracing (closed-loop skills from traces)**: Coding agent observability (Pydantic Logfire blog 13 Nov 2026, X announcement, docs and MCP server): harness sessions produce traces of model calls, tool executions, durations, costs, and subagents across harnesses. Logfire MCP lets an agent query those traces with SQL, surface repeated failures, and turn them into reusable skills. Example: a repeated failure distilled into a skill raised pass rate from 3/12 to 12/12 on the same scenarios. Contrast: opaque session logs are not queryable, SQL-addressable traces that close the loop into skills and evals. Heat 4. Shipping product + blog + X.

**EdgeQuake (PostgreSQL GraphRAG for MCP agent memory)**: LightRAG-style GraphRAG in Rust (raphaelmansuy/edgequake, Apache-2.0, recent reviews and v0.40.x notes ~9–11 Nov 2026): documents become entities and relationships in a single PostgreSQL store (pgvector + Apache AGE); hybrid vector+graph retrieval returns answers with sources. MCP server lets agents ingest, query multi-hop, explore neighbors, and persist memory across conversations without a separate graph DB. Accuracy ties the Python LightRAG reference on GraphRAG-Bench medical-mid (statistical tie); warm queries are faster with caching. Contrast: separate vector store + graph DB is not one Postgres + MCP relationship-aware memory. Heat 4. Shipping repo + recent write-ups.

# 2026-11-05

Harness-S (arXiv:2611.04277, 3 Nov 2026; code at github.com/DeepExperience/Harness-S): harness evolution from a common base shows locality, complementarity, and nonstationarity. Directional evolution builds a fixed sibling harness pool; complementary rescue training invokes siblings only on complete base-harness failures and transfers the resulting capabilities into a single policy that remains effective under the original harness. Adaptive router uses behavior profiles + multi-LLM voting. Across AppWorld, SWE-Gym, and DBBench the trained policy substantially outperforms policy-only training when returned to the base harness. Contrast: transferring complementary sibling-elicited behaviors into the base-harness policy is not seeking a single universally superior harness. Heat 4. Paper + shipping repo.

Do agents need to sleep? (arXiv:2611.02216, 1–3 Nov 2026, Haber & Tononi): persistent LLM agents accumulating memory already show semantic drift, degraded retrieval, stored-error propagation, and capacity saturation. The selectionist RRR account of sleep maps onto digital memory operations; engineers rediscover “what to forget and when.” Falsifiable prediction: selectionist consolidation will outperform instructionist (per-fact ADD/UPDATE/DELETE) methods as stores grow large. Core claim: plasticity has a price, and for continuous learning under finite capacity that price is sleep. Contrast: periodic offline selectionist consolidation is not continuous instructionist memory mutation. Heat 4. Paper + recent discussion.

Towards Portable Specification of the Agent Harness (arXiv:2610.40917, 29 Oct 2026): decomposes the harness into eight functional components that can be specified and compared, and proposes a portable versioned record of which model ran in which harness configuration within a run. Different harnesses yield several-fold score differences for the same model; much of the attack surface lives in the harness. Existing model/agent cards do not capture the sequence of effective configurations. Contrast: an explicit versioned harness record is not a model card. Heat 4. Paper + X discussion.

Production coding-agent audit discussion (recent X thread @damkina7, 3 Nov 2026, citing the July 2026 source study of 11 systems / ~4M lines): every production coding harness converges on seven subsystems (loop, LLM integration, tools/actions, memory/context, safety/permissions, orchestration, extensibility). Zero general agentic frameworks; zero vector RAG for code (ripgrep, tree-sitter, Markdown). Skills lead MCP (9/11 vs 8/11). 90-line minimal Python harness implements 10 patterns. Contrast: hand-rolled deterministic retrieval and native loops are not framework + vector-DB defaults. Heat 3 (durable paper + fresh discussion).

OO-Harness (arXiv:2610.28380, submitted 20 Oct, Li et al. / Google Cloud AI Research): evolves a hierarchy of executable harness classes via object-oriented inheritance; evolution agent creates specialized subclasses from execution records; test-time router selects using accumulated routing lessons. Best on three long-horizon benches (business workflows, workspace, tool use) with up to ~15% absolute gain over base; X discussion (Rohan Paul) restates specialized family + router vs global. Signal for hierarchical specialized harness evolution. Heat 4.

RiseHarness (arXiv:2610.27435, submitted 20 Oct, Wang et al.): reliability-oriented harness self-evolution for long-horizon terminal agents. Focuses on flipping tasks (success + failure under same config); contrasts trajectories + internal harness traces + Harness Handbook to locate shared mechanism defects; borrows designs from other frameworks; retains only measured gains. Improves Pass@1 and consistent-success fraction; treats a specific model as the adaptation unit. Signal for reliability gates in harness evolution. Heat 3.

HarnessPro (arXiv:2610.26770, submitted 19 Oct, revised 20 Oct): label-free recursive harness self-improvement with Pareto selection for performance-cost trade-offs. Emits lite/medium/heavy harnesses; heavy mode averages +2.0 pp pass rate and -26.1% cost vs prior RSI baseline on Terminal-Bench 2 / SWE-Bench Pro / ProgramBench. Signal for multi-objective harness evolution. (Note: unrelated Solana "Harness Pro" referral post marked heat 1 and skipped.) Heat 3.

SSR / Successive Scale Racing (arXiv:2610.28815, submitted 20 Oct, Liu et al.): addresses paradoxical degradation of harness evolution as task pool grows; adaptively searches optimal evidence combinations via successive scale racing under small budget. Improves as pool scales 40→200 (pass rate 64.3%→68.3%) while baselines drop; reduces validation executions ~60%. Signal for evidence selection in harness evolution. Heat 3.

CognitiveCanvas (arXiv:2610.23559, submitted 16 Oct, Hussain et al.): interactive GraphRAG workspace for conversational AI memories. Hierarchical Semantic Fact-Graph distills dialogues into Goal/Fact/Code artifacts (92.2% token reduction) enabling multi-hop traversal; temporal drift auditor; spatial-symbolic prompt compiler. Addresses flat-vector limits, silent context poisoning, and prompt bloat. Signal for audited context graphs over linear chat logs. Heat 3.

Neo4j Agentic GraphRAG blog (19 Oct https://neo4j.com/blog/agentic-ai/agentic-graphrag/): agent steers retrieval on knowledge/context graph (where to start, which tool, how far, whether to write back). Context graph extends domain KG with agent operational history. Reinforces existing neo4j-context-engine / context-graph nodes. Heat 3.

# Memory lifecycle

**Definition.** Policy over a durable archive that decides which stored facts may influence the current answer, which must be refreshed against the world, and which stay eligible only for historical queries. Not the graph schema and not the prompt.

**Contrast.** A write into memory is not a grounded working set. Grounding Agent Memory (2609.11060): a post-task curator restricted to finished trajectories can preserve errors, overgeneralize, or keep stale knowledge. Giving that curator least-privilege, read-only world tools — environment-probing curation — leaves the task agent, retriever, representation, and production write authority unchanged. GHCP SDK harness, CLBench pass 39% → 73%, reward 8.60 → 22.60, queries 8.8 → 4.7, cost $3.38 → $1.68; 18/18 APEX memory-vs-baseline mean rewards positive. RD-Forget (2609.10263): what is stored is not what is used. Keep the source archive; build a query-conditioned view. Same-slot replacement hides superseded values from current-state answers; intent-aware retrieval puts them back for a historical question. Dropping forgetting or dropping query conditioning produces the largest deficits. Fortunate Recall (2609.10413 + zenodo.20067778): an untyped personal fact is not a lifecycle. A 10+1 behavioral ontology plus deterministic decay / slot-key supersession / event-time validity / category routing. FR-Bank 76.9% on LifecycleBench vs 61–70.5% for Mem0 / A-MEM / Memory-R1 / MemoryOS. Generic lifecycle primitives carry correctness (−1.7 pp, 95% CI [−6.0, +2.7] vs the typed layer); the ontology halves confabulation 24.2% → 12.0%. Pair with EAL: a row that mints a grant is a failed lifecycle write. Pair with Selective Forgetting: deleting surface form is not the same as controlling influence. Pair with memory-graphs: the graph is the address space; the lifecycle is which addresses the current view may touch.

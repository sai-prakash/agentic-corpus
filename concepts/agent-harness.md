# Agent harness

**Definition.** The runtime around a frozen model: tools, memory, planning, verification, budgets, lifecycle hooks. Not the model.

**Contrast.** A framework is one packaging of harness jobs. The harness is the job list and the IP. Same Model, Different Harness (2608.26218): tight-window context policy moves SWE-bench Verified F2PF 28% → 49% with weights frozen. EvoHarnessBench (2609.04280): adding tools, skills, or specialist agents is a harness change that can *drop* previously solved tasks — agent-axis backward transfer −34.7% on the largest ALE deployment cell. YC (7 Sep): same weights, ARC-AGI 30% → 95% when the cage changes. ContextPipe: assembly is a query plan with an EXPLAIN trace, not a growing string. TROVE: the planned suffix is provisional once a runtime outcome lands. PlanFence: the harness that executes must validate the plan's cited records, not only refresh the replica. Persistent Agents: the current model+harness pair is a binding, not the agent. Substrate-aware (2609.05232): RAM and wall-time belong in the planning state; omitting them is substrate blindness, not a cleaner prompt. Interchangeability (2609.05279): a role-matched specialist swap is a harness event even when the scoreboard is flat — communication per unit of progress still moves. Multi-Harness RL (2609.04518): training across Aider / OpenHands / Qwen Code / SWE-agent does not wash the cage out of the policy. The eval harness moves sealed solve rate ×4.3; Cross-group credit adapts to configuration and does not beat Within on a held-out minimal harness.

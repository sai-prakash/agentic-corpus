# Agent harness

**Definition.** The runtime around a frozen model: tools, memory, planning, verification, budgets, lifecycle hooks. Not the model.

**Contrast.** A framework is one packaging of harness jobs. The harness is the job list and the IP. Publish angle: if adding a tool drops yesterday's pass, you measured the catalog, not the agent. Benchmark the solver, not the checkpoint. Name the machine before the first plan. Name who owned the execution-critical step before you publish a model ranking. Name the grouping boundary before you claim the policy transferred. If the cage is hosted, name where the grant lives. If you rent a lab harness API, delete glue that is not the domain job; if you write a domain harness, write the guards first. If a list is missing, assume every server. If the miss was fixed by hand, the harness did not learn. If native beats generic only on contest tasks, publish the stratum, not the average. If you credit a plan, run the Sham control. If you credit a verifier, report withheld-correct, not only blocked-wrong. If you credit an efficiency loop, publish traffic and withheld work, not only solved tasks.

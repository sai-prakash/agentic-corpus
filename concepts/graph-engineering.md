# Graph engineering

**Definition.** Explicit evolving graphs of tasks, agents, and system state. Also used sloppily for knowledge-graph memory. Keep knowledge graph vs control graph vs context graph apart.

**Contrast.** Graph engineering is not "add a KG to RAG." The survey (2608.21156) is system intelligence: organize work, coordinate heterogeneous agents, maintain evolving execution state. Year of the Graph (31 Aug): GraphRAG sits on the retrieval path; graph memory organizes what agents know and have done; a GNN takes the graph as native input. IBM VLDB: the structure-boundary question is how much of that graph to materialize before retrieval versus leave to traversal and the reader. Extra schema that the retriever never walks is inventory. DNative-Twin (2609.03787): a committed decision is a typed trajectory — observed state, path, authority — replayed under declared conditions. Graph structure localizes a represented change. It cannot decide the consequence of an unobserved tool state until replay-contract state and verification evidence are attached (unresolved-divergence recall 0 → 0.667 → 1.0 on 300 injected instances). That is a control graph with a gate, not a retrieval graph. Codebook Agent (2609.02264): the useful multi-agent control graph is a short list. Reward-surviving topologies collapse to about six families as codebook capacity grows 8 → 64; edge count correlates negatively with measured tokens (r ≈ −0.4); a message-passing scorer over shared agent profiles cannot see the adjacency it claims to rank. Index the six, do not search N×N. Best fixed family stays within 1.4 accuracy of generated graphs. Procedural Graphs (2609.09153): the missing fourth object is a *procedure* graph — (procedure, relation, procedure) for what-to-do, localized to the active node, edited only when held-out validation does not drop. 19/24 wins vs strongest baseline; EnterpriseArena survival Gemini 3.1 Pro 34.0 vs 6.0. A KG of facts does not tell the solver which tool is legal next. Personalized-memory survey (2609.08599) restates representation / evolution / retrieval / evaluation for user graphs — vocabulary under memory-graphs, not a new paradigm. LiteRAG (2609.10239): GraphRAG Global / DRIFT query-time LLM control is not required for multi-hop quality — DistComp 0.798 with >100× lower latency and >99% lower cost vs those modes. Mosaic (2609.11065): if you keep a walker, do not share one width. Per-query bounded policy over seeds, traversal, stop, and evidence; graph and generator frozen. GraphRAG-Bench +5.13 / +4.43 over prior overall reports; +9.96 vs strongest fixed narrow/medium/wide policy on the same graph; 81.9% fewer paths than Fixed Wide. A shared walk is inventory. A per-query policy is a control graph over retrieval. HCRG (2609.12464): vector chunks sever inheritance. AST → property graph → context cache, parent-first, cuts API hallucination 56.4% → 16.2% and raises dependency resolution 34.8% → 65.9%, while cyclomatic consistency falls 71.6% → 46.7%. Topology is not free density. GraphEcho (2609.17695): more paths are not more independent evidence. Hold content fixed and vary path count vs origin; redundant supporting paths raise repeated walks on every frozen agent tested. Provenance-aware post-training cuts revisits and lifts synthetic accuracy, then covers fewer distinct sources; on scientific claims repetition falls and accuracy falls with it. EffiRAG (2609.18099): a graph that locates original passages is priced; a graph that restates them is inventory. UltraDomain 120 questions: preferred 93 vs LightRAG-hybrid 7 (20 splits); ingest+query cost $0.952 → $0.408 (−57%). At 10 / 20 docs per domain a non-LLM salience filter keeps the preference at 4.2× / 4.5× lower cost. RAFT (2609.20754 + microsoft/RAFT): retrieve the timeline entry that matches the live stage, then return the parent trajectory. Fast-GraphRAG 42.1% Case Hit at 0% progress vs RAFT 84.2% on the synthetic Windows Server set. A case graph that treats tickets as documents is inventory. TRACE (2609.19897): accountable agentic retrieval over OCR archives beats graph-construction baselines on HistoriQA (R@10 0.856) without a new KG.

Publish angle: the survey is the citation; the lab is the proof. Ignore "95% of developers use graph engineering" wraps. A decision graph that cannot replay tool state is a drawing. A topology search that rediscovers six graphs is inventory. A procedure graph that cannot fail a held-out ticket is a diary. A GraphRAG that uses one walk for every question is the same inventory on the retrieval path. A global cache that over-engineers the child class is still a control-graph miss. A walker that revisits the same origin is not corroboration. Price the structure that locates sources; do not pay twice to restate them. A closed ticket retrieved as a blob is not the stage the live case is in.

# Harness evolution

**Definition.** Improve the wrapper, not the weights. Outer loop proposes harness changes; evals keep or reject.

**Contrast.** StarHarness / Recuris still assume a human or search loop over harness code. JIT-Agent trains a generator that emits the harness at task time. Harness-G changes the *interface* (finite graph actions, not free-form queries). HarnessLens changes the *verifier*: do not score every candidate on a fixed task set. Predictable harness (2608.26197): a first-pass FSM wrapper is mixed; the leftover variance is unconstrained free-text planning. Schema-validate the plan before any tool and three of four cells hit reproducibility 1.000 at N=100. Self-orchestration (2608.26480) is a one-shot scaffold change, not an evolution loop — gains are real and model-conditional. openJiuwen (2608.27969): the missing pair is Structural Composability plus Runtime Adaptivity — Rails under one substrate, evidence moves framework decisions, model policy stays fixed. EvoUndo (2608.28363): a mutation that raises the score is not admissible until recoverability holds on counterfactual states. Warp: the searchable object can be a skill file. Inner skill executes; outer skill reads human corrections and opens a diff. That is evolution with a merge gate, not mid-task CRUD on the prompt. Harness-of-Harness (2609.01481): the outer object is a plan–code–test loop over an *existing* coding harness. Implementation-time tests stay inside the loop; independent evaluation scores the iteration. Average relative +52.25% after three iterations on three harness–model pairs; 70+ unattended loops produced a playable game. HarnessEvolve (2609.00829): credit assignment needs a reference trajectory (the run given the gold answer), not a terminal bit. Quality gate kills leakage and prompt bloat; performance gate refuses an edit that lifts this batch and drops recent ones. HarnessDev (2609.01437): the model is asked to *create* the harness from a weak seed, then evolve it for 10 rounds. Feedback-set gains (+3 to +14) shrink on held-out (+1.4 to +4.4); under a fixed executor only Opus stays positive. Self-chosen finals are held-out best 2/9 times. Read-failure-then-patch correlates 0.57 with score; stacked self-tests do not. Environment Evolution (2609.04128) evolves the *room* off-policy, not the cage file — keep the objects apart. Terminal-Universe (2609.04148) recovers the room from the trace: replay file ops to the pre-edit state, complete the missing tree, then synthesize new tasks across workspaces and rounds. 37.3k recovered environments; Qwen3.5-27B SFT +11.9 Terminal-Bench 2.1 / +13.8 EvoCode-Bench v2 MT@4; training on recovered intent beats training on the source traces. DRACO (2609.04094) is the credit half of an evolution loop when there is no checker: a rubric score that cannot name the step is not a mutation signal. BCIT (2608.26730) is the same gate one layer down on *weights*: a past update that helped a prior parent is not authorized on the current one until a bounded trial says so. 13/24 naive reuses failed the new context; harmful authorization 62.5% → 25.0% under the calibrated rule. EvoHarnessBench (2609.04280): those loops assume the catalog is the thing you *edit*. When the catalog is the thing that *arrives* — 520 tools, 42 skills, 62 agents, released long-tail first from two verifier benches — expansion alone forgets (BWT −5.3 / −4.0 / −34.7 on the three axes). Adaptation methods that persist state can lift the new stage (Meta-Harness +110.2% agents on EOG vs deployment) without restoring the old one. Retention and adaptation are not the same gate. SafeEvolve (2609.02786 + MaoPopovich/SafeEvolve): the artifact under evolution can be a *safety* prompt plus hierarchical SkillBank. On-policy traces become bounded reversible edits; harness-use SFT then harness-augmented GRPO teach the policy to use them. Qwen3.5-4B AgentDojo ASR 2.37% → 0.79% with utility 59.79% → 61.86%; AgentHarm harm 56.45 → 12.27, refusal 28.98% → 83.83%. Competence gates and safety gates are the same shape with different oracles. Multi-Harness RL (2609.04518): evolving or training *across* cages is not the same as portable capability — Cross-group credit adapts to configuration and does not transfer extra skill to a held-out minimal harness. RobustSGPO (2609.09646): a local semantic-gradient edit is not a search-space policy. Specify the requested edit, construct and check the patch, continue from the incumbent or a retained snapshot. Periodic 1→2→3 permission scheduling beats always-max by 0.28 test-score points on AgentX (120 tasks, 95 runs, 7,350 attempts). Held-out completion 60.0% → 80.0%, quality 3.77 → 4.14 under a 20M-token budget. Category retention protects the source family after a shift; random retention reaches a higher destination endpoint. The permission to search is part of the harness. All of these are harness work, not model work — except BCIT, which is the same refusal applied when someone *does* change weights.

Publish angle: keep the model, evolve the cage, show the diff. Gate the diff on the behaviors it claims to change, on recent batches it must not drop, on whether you can undo it on a second state, *and* on whether a second model can execute the same file. If the cage grows under you, measure forgetting before you celebrate the new tool. If you only have traces, recover the environment before you train on the demonstration. If you do change weights, bind the last win to the parent it was measured on. If the artifact is a safety skill, keep the same rollback. Do not leave the edit-scope permission on maximum for the whole search.
